# Secure Vercel Preview configuration

The confirmed failure was `Error: JWT_SECRET must be a new random secret of at least 32 bytes` at `signingKey (src/lib/token.js:12:11)` and `next.config.mjs:2:44`. It happened during configuration loading. The build no longer needs the key, but authentication and contact rate limits require a valid key at runtime. No fallback is generated by the application. A passing build without runtime configuration is not a functioning Preview.

## Administrator steps (Preview scope only)

1. Create a separate non-production PostgreSQL/Supabase project with synthetic data and a reviewed original schema. Rehearse the versioned private-schema migration using a trusted operator after checking provider restrictions. Never connect Preview, test scripts or migrations to the Production project. Apply the runbook's access checks even for provider-hosted rehearsals. The local test-baseline script is a fixture, not a production baseline/migration. Provision a separate Preview administrator through an explicitly authorized provisioning identity/policy, with a unique password; the runtime cannot insert User rows and FORCE RLS restricts owners too. Never reuse the production administrator/password or copy real customer records into Preview.
2. In Vercel project Settings → Environment Variables, select **Preview** (and the intended branch scope, if applicable). Set the variables below using the secret manager or encrypted UI. Review inherited/shared integration variables and branch overrides: Preview must not inherit Production's database, signing key or SMTP credentials. Keep DATABASE_URL and JWT_SECRET sensitive; never prefix them NEXT_PUBLIC. Do not paste values into GitHub or build logs.
3. Generate Preview JWT_SECRET independently with a cryptographic generator, for example `openssl rand -base64 48`, in a trusted local terminal and transfer it securely. Do not run this in CI logs or commit its output. Missing keys, fewer than 32 UTF-8 bytes, leading/trailing whitespace, obvious repeated patterns and the published legacy key are rejected. Length/pattern checks cannot prove entropy. Use an independently generated value per isolated environment; all instances of one Preview environment need the same key. No production rotation is requested.
4. Set DATABASE_URL to the isolated project's narrowly privileged aljalal_app login after the migration and reviewed login/password provisioning. Verify actual custom-role pooler username and Prisma 6 compatibility. For Supavisor transaction pooling, review `pgbouncer=true` and an initial `connection_limit=1` budget; use direct/session operator access for SQL. Verify TLS and provider restrictions live as described in the deployment review. Do not place the owner/operator URL in Vercel.
5. Review Vercel's install/build/root-directory/Node settings against the repository (`npm ci`, `npm run build`, Next.js, CI Node 24). Do not add a migration or seed to the build. After settings are approved, trigger only a Preview build and test public content, inquiries, administrator login, role denial, sessions and sandbox mail. This task did not change Vercel settings or manually trigger deployments.

| Variable | Preview requirement | Scope and purpose |
| --- | --- | --- |
| DATABASE_URL | Required for functioning application | Private, runtime; isolated migrated app_private database and aljalal_app login. Some build data collection may access the DB; grant no production access at build time either. |
| JWT_SECRET | Required for authentication and inquiry rate limits at runtime | Private; independently generated random Preview secret. Not required merely to load config or compile. |
| NEXT_PUBLIC_SITE_URL | Set for correct Preview metadata/sitemap | Public HTTPS origin of this Preview environment; never a credential. The code has a production-origin default, so explicitly override for Preview. |
| SMTP_HOST | Required only when testing notification delivery | Sandbox SMTP host, separate from Production. |
| SMTP_PORT | Required only when testing notification delivery | Sandbox port. |
| SMTP_SECURE | Required only when testing notification delivery | `true` for implicit TLS; use the sandbox provider's supported TLS configuration. |
| SMTP_USER | Required only when testing notification delivery | Sandbox sender/login. Override the application's existing sender default. |
| SMTP_PASS | Optional; required for notification delivery | Private sandbox credential. Leave unset to skip notifications while preserving inquiry persistence; do not inherit Production's password. |
| NOTIFICATION_EMAIL | Required only when testing notification delivery | Controlled test recipient; override the existing real-recipient default. |

ADMIN_EMAIL and ADMIN_PASSWORD are manual provisioning inputs, not Vercel runtime settings. Deliver them only to the reviewed isolated provisioning process. Do not set a default administrator password, enable seed-on-deploy, or grant User writes to the runtime. No SUPABASE_SERVICE_ROLE_KEY, anon key, owner URL or extra JWT fallback variable is required by this Prisma/custom-auth application. Vercel supplies platform environment identifiers; do not use them to bypass security checks.

The notification email currently contains a localhost dashboard link; this is a pre-existing notification usability limitation, independent of JWT deployment failure. Preview delivery must use a sandbox. No application or TLS behavior is inferred merely from a successful build.

## Production compatibility blocker

The candidate Prisma models target app_private, while Production has not been migrated from public. Pointing this candidate at Production can break public content and authentication even if the Vercel build succeeds. Keep automatic Production promotion blocked by the release process. Only the separately approved, backup-verified and rehearsed runbook can authorize database/application cutover. Do not merge or promote this PR as part of Preview repair. All live Supabase findings, role/provider behavior, pooler behavior and backup evidence remain verification gates.
